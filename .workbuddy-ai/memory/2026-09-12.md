# 2026-09-12

## 在本地跑起 alien-form（Windows）

### 环境
node v22.22.2 / pnpm 9.15.0，依赖已装，`packages/*/dist` 已存在。

### 问题 1：根目录 `pnpm dev` 在 Windows 不可用
两个原因叠加：

1. `apps/alien-worker` 的 dev 脚本用了 bash 风格环境变量前缀
   （`XDG_CONFIG_HOME=... wrangler dev`），pnpm 在 Windows 默认用 cmd.exe 执行脚本，
   报 `'XDG_CONFIG_HOME' 不是内部或外部命令`。
2. 把 pnpm `script-shell` 改成 Git Bash 后，`vite` 垫片又崩：
   本机全局设置了 `MSYS_NO_PATHCONV=1` 与 `MSYS2_ARG_CONV_EXCL=*`，
   Git Bash 不再做路径转换，垫片里的 `/c/...` 被 node 解析成 `C:\c\...`。

**解法**：新增 `scripts/dev-windows.sh` —— 绕开所有 shell 垫片，直接用
`node ./node_modules/<pkg>/bin/<entry>.js` 启动，全程使用相对路径。
脚本会先跑幂等的本地 D1 迁移，再并行启动两个服务并给日志加 `[web]` / `[worker]` 前缀。

```bash
bash scripts/dev-windows.sh
```

### 问题 2（真实 bug）：兜底路由打挂 wrangler dev
访问 `http://127.0.0.1:8787` 时（wrangler 直接服务 `apps/alien-mdm/dist`），
旧版 SPA 会 POST `/api/auth/login`（该 dist 是 2026-08-26 的产物，硬编码 `"/api"` 基址；
当前源码已改为 `/api/v1/...`）。

该路径不存在 → 落到 `app.all("*")` → 把**带 body 的 POST 转发给 `ASSETS.fetch`** →
workerd 抛 `Can't read from request stream after response has been sent`，
此异常不受 Hono `onError` 保护，**直接打挂 wrangler dev 进程**（前端表现为 502 ECONNREFUSED）。

**修复**（`apps/alien-worker/src/index.ts`）：
- 未匹配的 `/api/*` 返回 404 JSON 信封，不再回落到 SPA
  （此前 `/api/health` 这类错误路径会返回 200 HTML，很误导）。
- 非 GET/HEAD 请求返回 405，只有 GET/HEAD 才转发给静态资源。

同时 `apps/alien-worker/src/http/envelope.ts` 的 `StatusCode` 增加 `405`。
`tsc --noEmit` 通过。

- `POST /api/v1/auth/login`（`_sys_admin` / `alien123456`）→ 200，返回 token
- 带 token `GET /api/v1/models` → 200，返回 `_sys_user` 模型
- 旧路径 `POST /api/auth/login` → 干净的 404 JSON，worker 存活
- `POST /index.html` → 405；`GET /some/spa/route` → 200（SPA fallback 正常）

## 补充（同日 14:45）：上面这条「已知遗留」已解决

用户反馈「没有跑起来，http://127.0.0.1:8787/login 是前端」——
两个服务其实都在跑，问题是 **8787 服务的是 8-26 的旧 dist**，
旧前端调 `/api/auth/login`（已被改成 `/api/v1/...`），所以登录必然失败。

### 真实根因：工作区包 dist 过期
`apps/*` 通过 package.json 的 `exports` 解析到 `packages/*/dist`，**不是 src**。
`packages/engine` 与 `packages/react` 的 dist 停留在 2026-08-26，
而源码是 2026-09-12 —— 所以 `ComponentProps` / `SchemaComponent` / `usePage` /
`ValueSource` / `useRuntime` 这些**源码里明明存在**的导出，在 dist 的类型声明里没有。

**修复**：

```bash
pnpm --filter @alien-form/engine --filter @alien-form/react run build
pnpm --filter @alien-form/alien-mdm run build     # 之后即成功
```

### 脚本已加固
`scripts/dev-windows.sh` 新增第 0 步：对比
`packages/{core,engine,protocol,react}/src` 与各自 `dist/index.js` 的 mtime，
过期才重建，避免每次启动都付构建成本。
`builder` / `shared` 无 src 无 build 脚本，是纯产物包，跳过。

### 最终验证
- `GET http://127.0.0.1:8787/login` → 200，引用 `assets/index-CAlibA7N.js`（新产物）
- `POST http://127.0.0.1:8787/api/v1/auth/login` → 200，返回 token
- `POST http://localhost:5173/api/v1/auth/login` → 200
- 新 dist 中已无 `/api/auth` 旧路径，全部为 `/api/v1/*`

## 补充（同日 14:52）：把启动脚本写进 package.json

需求：希望能用 `pnpm xxx` 一条命令启动。

### 为什么不能直接写 `"dev:win": "bash scripts/dev-windows.sh"`
实测确认：系统 PATH 里的 Git 项只有 `C:\Program Files\Git\cmd`，
而 **`bash.exe` 位于 `C:\Program Files\Git\bin`，不在 PATH 上**
（`C:\Program Files\Git\cmd` 里只有 git.exe / git-lfs.exe / scalar.exe 等）。

pnpm 在 Windows 用 cmd.exe 执行脚本，因此从 PowerShell / Windows Terminal
运行时会报找不到 `bash`；只有从 Git Bash 启动才行。

### 做法：改成 Node 启动器
- 新增 `scripts/dev.mjs`（Node，跨平台）。用 `child_process.spawn(process.execPath, …)`
  **不经 shell** 启动子进程，一次性规避三个坑：cmd 的环境变量前缀、MSYS 路径转换、
  shell 垫片。
- 删除 `scripts/dev-windows.sh`（已被完全取代，避免两个入口重复）。
- `package.json` 新增 `"dev:local": "node scripts/dev.mjs"`。

### 功能
1. 产物过期检测：`packages/{core,engine,protocol,react}` 的 src 比 `dist/index.js` 新才重建；
2. 应用本地 D1 迁移（幂等）；
3. 并行启动 worker(8787) + web(5173)，日志带 `[worker]` / `[web]` 前缀；
4. Ctrl+C 时用 `taskkill /T /F` 结束子进程树（wrangler 会派生 workerd）；
5. 任一子进程意外退出则停掉另一个并以非零码退出。

### 验证
- `pnpm dev:local` 启动成功（这条路径正是之前会失败的 cmd 路径）。
- 接口：8787 `/login` 200、8787 登录 200、5173 登录 200。
- 过期检测：`touch packages/react/src/index.tsx` 后重启，
  输出 `==> 工作区包产物过期：react —— 正在重建`，重建后 dist 变新，再次启动不再重建。

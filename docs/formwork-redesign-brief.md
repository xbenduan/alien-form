# Formwork 重构任务边界

本任务将 alien-form 重构为低心智负担的 headless 数据管理框架，并完成当前应用与最小独立项目的接入。本文包含后续对话确认的范围；最终实现见[重构设计](formwork-redesign-exploration.md)和[验收记录](formwork-redesign-review.md)。

## 使用者需要完成的工作

开发者声明数据 API、视觉组件、UI 映射、Domain 和 Page，即可让模型复用查询、表单、详情和记录 CRUD。框架处理模型加载、值约束、状态及操作生命周期，业务代码保留布局和定制权。

低心智负担以必要决定、重复声明、隐式规则及排错成本衡量，不单看 API 数量。普通模型复用 list，需要特殊布局时组合 `formwork/atom`，不为每种布局增加框架层级。

## 已确定的架构要求

| 要求        | 约束                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| headless    | app 提供 components、ui 和原生嵌套 CSS；框架不绑定视觉库                         |
| 显式注册    | `defineFormwork({apis,components,ui,domains,pages})`，两个路由数组来自各自 index |
| 目录        | `domains/list`、`domains/tree`、`domains/videos` 分别实现，domains/index 只汇总  |
| Domain      | `defineDomain({router,render,transformSchema?})` 映射 `/router/:modelId`         |
| Page        | 与 Domain 并列，声明普通 `/router` 页面                                          |
| 业务分类    | `schema.domain` 只表达模型分类，业务代码按需判断                                 |
| Schema 加工 | 修改运行时副本，返回同一个 ctx；按 app → Domain → 局部执行                       |
| 原子组合    | Records、Detail、Editor 及必要部件可在真实 JSX 中组合                            |
| 数据服务    | 校验、权限和条件写入由服务端执行，不依赖 UI 是否隐藏                             |

组件名在 Schema 和 ui 中引用，真实组件集中注册到 app.components。展示覆盖应在相关编辑、详情和预览中复用；局部例外有明确作用域。

## 本次实现范围

1. 完成框架内核、公共 API、当前应用及独立最小项目，不只交付设计或接口。
2. list 是默认正式场景，覆盖记录 CRUD、筛选、分页、关系、复杂字段和操作生命周期。
3. tree-list 和 videos 只写简单示例，验证自定义布局复用 controller 与 Detail。
4. richtext 使用最简单的字符串和多行输入示例，不引入专业编辑器。
5. 模型管理、草稿预览、发布、版本、认证、角色及 MCP 接到当前 API。
6. 删除不必要脚本、旧 Window 机制和 JSX 转换；构建插件只承担可选静态能力发现。

此次按从未部署的项目处理，允许直接更改 API 和数据协议。**不迁移历史数据，不保留历史协议转换或升级脚本。** 这是后续对话对最初迁移要求的明确修订。普通开发启动保留本次协议产生的数据，显式重置另设命令；后续发布仍需要数据一致性校验。

## 验收场景

| 场景     | 预期                                              |
| -------- | ------------------------------------------------- |
| 新项目   | 独立 API 适配器和 UI 可运行，不复制整个 CMS       |
| 标准模型 | 发布后直接使用默认 list，不重写 CRUD              |
| 统一定制 | app 和 Domain 的加工按顺序应用，预览复用正式规则  |
| 特殊布局 | 共享 controller、字段渲染和详情出口               |
| 编辑流程 | 取消、保存、刷新、直达、历史导航和未保存保护正常  |
| 复杂字段 | 对象、数组、关系及 null/缺失值语义一致            |
| 并发     | 模型和记录冲突不覆盖其他写入，失败保留输入        |
| 预览     | 内存记录与正式数据库隔离，支持未保存的有效 Schema |
| headless | 数据入口不依赖 DOM，HTTP/MCP 遵守后端权限         |

验证采用构建、类型检查、Vitest、真实浏览器 E2E、本地 Worker/D1 和 dry-run 打包。正式部署及外部数据变更不属于本次开发验收。
